# 投射物动态迭代与验证

用于箭雨、弹幕等投射物群的视觉迭代，以及“穿过本人/友军却爆闪消失”的问题。仅对当前反馈选择相关检查，不因读到本参考扩大为全库预览、其他技能改造或多人验收。

## 先锁定玩家所指的效果

- 从用户指定的具体系统和配方版本出发，在可重置场景查看发射、飞行、命中和消散。名称、静帧、相似轮廓不足以证明运动、波动或能量感匹配。
- 改造前识别主体、拖尾、材质运动、子发射器及事件依赖。保留选定源系统的关键动态关系，修改当前反馈对应部分；确需替换主体时说明哪项要求原系统无法满足。
- 用相同机位、距离、播放时间段和场景对比。快照用于构图，动态片段用于时间行为；只看若干帧时如实记录，不能称为完整动画审查。

## 范围、密度和行程分开量测

- 将“扩大两倍”等相对描述换算为基于当前值的米/厘米目标。分别记录发射面宽高、沿途覆盖、最大飞行距离与伤害范围，避免把其中一个当成其他指标。
- 同时检查发射率、持续时间、寿命/速度与投射物间距。宽度或面积增大而总发射率不变时，局部观感会变稀；率×寿命可估计稳定在场数量，率÷宽度/面积仅用于比较密度，不是艺术验收阈值。
- 配置的速率/总数与实测分开。对已声明时段记录实际生成数、空间覆盖、提前碰撞/终止和回收；帧率、遮挡及采样缺口限制应随证据保留。不要把某次技能的宽度、速率或总数写成全技能默认参数。

## 穿透验证必须落到同一投射物

- 用户报告实际箭体在友方处消失时，重新复现这一行为。血量不变、Primitive `Ignore`、独立 LineTrace 无命中，都不能单独证明 Niagara 的碰撞、终止与事件链允许穿透。
- 在受影响的真实路径上，用稳定粒子 ID 或等价可追踪身份确认同一投射物在穿越前后继续运动，并且没有触发不应发生的爆闪、命中事件或销毁。CPU/GPU 或工具限制使身份不可追踪时明确标记证据缺口，不能用无伤害代替通过。
- 同时覆盖本人、友军以及受影响的阵营变体；检查敌方/地形仍按设计触发命中或终止，且伤害保持服务器权威。表现系统与伤害系统的阵营过滤分别验证，不能只修其中一条链。
- 记录源系统实际启用的碰撞、`HasCollided`、年龄/寿命、Kill 和子事件关系后再决定修复。不要把某次关闭作者 Collision、改用自定义查询的实现推广成通用方案。

## 保持迭代短且可追溯

每轮只处理当前差异，给出一份可直接体验的动态结果；复用未变化的工程证据，重测受影响行为。用户反馈绑定配方、媒体、机位和当前保留项，下一轮不能无意丢失已经认可的范围、运动或动作。完成相关验证和保存即交付，不为已收敛候选追加无关全量检查。
